# 保存値と比較するテストが別の計算機で落ちる原因 (2026-11-14)

README の手順 1 を別の計算機 (クラウドのコンテナ, CPU のみ) で実行したところ, `uv run pytest` が既知の 1 件に加えて 18 件失敗した.
その原因を調べた記録.

## 結論

- 原因は 2 つあり, どちらもコードの不具合ではなく, 保存値が計算機に依存していること.
  1. **unlabeled の並びがファイルシステム依存** (主因). `UnlabeledSet` が `glob.glob` の結果を並べ替えずに使っている.
  2. **浮動小数点の丸めがスレッド数に依存** (残りの差). 許容幅 (相対 1e-6) より大きく動く値がある.
- 1 を保存値を作った計算機の並びに合わせると, `mt` の不一致は 101 / 142 から 33 / 142 に減り, student の損失はすべて一致した.
- 残った 33 件は teacher 側の値が中心で, 同じ計算機でスレッド数を変えるだけで同じ大きさ (最大 5e-4) で動く.
- 保存値を作ったコミット (`b5aeb57`) でも同じ値で落ちるので, その後のコード変更は原因ではない.
- 実データの学習でも 1 は同じで, 計算機が違うと unlabeled のバッチの中身が変わる.

## 症状

| 項目 | 内容 |
|---|---|
| 環境 | Linux, ext4, CPU 4 コア (AVX512), GPU なし, torch 2.8.0+cu128 (`uv.lock` のまま) |
| コマンド | `uv run pytest` (commit `d7ee9d1`) |
| 結果 | 19 failed, 45 passed (4 分 47 秒) |
| 失敗の内訳 | `test_synthetic_metrics_unchanged` 7, `test_synthetic_trace_unchanged` 7, `test_variant_numbers_unchanged` 4, 既知の `test_evaluate_psds2` 1 |

- 学習・評価は完走していて, 保存値 (`tests/synthetic_expected.json`, `tests/synthetic_expected_trace.json`) との比較だけが落ちる.
- `mt` の最初のステップの `train/student/loss_strong` は 0.3442748 (保存値 0.3442716).
- 同じ計算機では何度流しても同じ値になる.

## 原因 1: unlabeled の並び

`desed_task/dataio/datasets.py` の `UnlabeledSet.__init__`:

```python
self.examples = glob.glob(os.path.join(unlabeled_folder, "*.wav"))
```

`glob.glob` の順はファイルシステムが返す順で, 計算機ごとに違う. `RandomSampler` が選ぶのは添字なので,
seed が同じでも並びが違えばバッチに入るファイルが変わる. 他のセット (strong / weak / synth / MAESTRO) は tsv の行順で決まるので影響を受けない.

確認した手順 (`mt` の `test_synthetic_trace_unchanged`, 比較対象は 142 個の値):

| 並び (`unlabel_N.wav` の N) | 保存値との不一致 |
|---|---|
| この計算機の並び `5,2,4,3,0,1` | 101 / 142 |
| 昇順 `0,1,2,3,4,5` | 99 / 142 |
| 降順 `5,4,3,2,1,0` | 101 / 142 |
| **`3,2,1,0,4,5`** | **33 / 142** |
| 先頭が `3,2` の残り 23 通り | 81〜94 / 142 |

- 並びの差し替えは, テスト実行時に `glob.glob` の結果を入れ替える調査用の pytest プラグインで行った (リポジトリには入れていない).
- 最初のステップで使われるのは並びの先頭 2 件. その組 30 通りのうち, 保存値に近いのは `3,2` だけだった
  (最初のステップの損失の相対差が最大 1.1e-5. 他の 29 通りは 7.8e-3 以上).
- 先頭を `3,2` に固定して残り 24 通りをすべて試し, `3,2,1,0,4,5` で `train/student/loss_strong` などの student の損失が全ステップで一致した.
- 並びを `3,2,1,0,4,5` にして全テストを流すと, 全構成で不一致が減った (途中経過: 100〜124 件 → 23〜46 件, 最終指標: 12〜14 / 24 → 1〜5 / 24).
  ただし失敗の件数は 19 のまま (原因 2).

## 原因 2: スレッド数による丸めの差

並びを合わせた後に残る差は相対 1e-6〜5e-4 で, teacher の出力と validation の teacher の指標に集中している.
同じ計算機・同じ並びで条件だけを変えて, 1 スレッドの結果と比べた.

| 条件 | 1 スレッドとの差が 1e-6 を超えた値 | 最大の相対差 |
|---|---|---|
| 2 スレッド | 36 / 142 | 5.4e-4 (`val/teacher/segment_f1_macro_thresopt`) |
| 4 スレッド | 49 / 142 | 4.5e-4 (`val/teacher/segment_mauc`) |
| 命令セットを AVX2 に制限 | 12 / 142 | 3.4e-6 |
| 命令セットを SSE4.2 に制限 | 10 / 142 | 5.5e-6 |

- スレッド数を変えるだけで, 保存値との残りの差と同じ値が同じ大きさで動く.
- 試した条件のどれでも保存値とは一致しなかった (不一致 31〜43 / 142).
- テストはスレッド数を固定していないので, コア数が違う計算機では原因 1 が無くても落ちうる.

## 否定した仮説

- **保存後のコード変更**: 保存値を作った `b5aeb57` を取り出して同じテストを流し, 同じ値で失敗した.
- **依存ライブラリの版**: `uv.lock` どおりにインストールしている.
- **実行ごとの揺れ**: 同じ条件では毎回同じ値になる.

## 影響

- README の「`test_evaluate_psds2` 以外が通れば環境は出来ている」は, 保存値を作った計算機でしか成り立たない.
  別の計算機では `test_synthetic_*` と `test_variant_numbers_unchanged` が落ちても環境は正常でありうる.
- `uv run poe test` (軽いテスト) は影響を受けない. 学習〜評価が完走するかを見る `test_repro_variant_end_to_end` なども通る.
- 実データの学習でも unlabeled の並びは計算機ごとに違う. 同じ seed でも計算機が違えば unlabeled のバッチは一致しない.

## 対処の案 (未実施)

1. `UnlabeledSet` の `glob.glob` を `sorted(...)` で包む. 並びが計算機に依存しなくなる.
   実データの学習でも unlabeled の順が変わるので, 既存の再現値とは同じ seed でも一致しなくなる (もともと `deterministic: False` で一致しない).
2. テストでスレッド数を固定する (`torch.set_num_threads(1)`). これだけで足りるかは未確認 (命令セットでも 1e-6 を超える差が出ている).
3. 比較の許容幅を緩める. 今回見えた丸め由来の差は最大 5.4e-4 なので, 相対 1e-3 程度が目安. 実際に通るかは未確認.
4. 1〜3 の後, 保存値を取り直す (`UPDATE_SYNTHETIC_EXPECTED=1 uv run pytest -k "synthetic or variant"`).

## 未確認

- 保存値を作った計算機の実際の並びとスレッド数. `3,2,1,0,4,5` は総当たりからの推定.
- 詳しく調べたのは `mt` だけ. 他の構成は「並びを合わせると不一致が減る」ことまで.
- 残りの差が teacher 側に集中する理由.
- GPU での挙動.
